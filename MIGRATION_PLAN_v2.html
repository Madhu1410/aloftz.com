§ 03 — Apache Configuration

Complete .htaccess — Drop-In Replacement

This is your full, production-ready .htaccess. It replaces your existing file entirely. The order of rules is critical — do not reorder them.

Rule Order Matters

Rules execute top-to-bottom. HTTPS enforcement must be first, then www redirect, then .html → clean URL 301s, then clean URL → .html internal rewrites, then the SPA fallback last.

  old=$(echo $pair | awk '{print $1}')
  expected=$(echo $pair | awk '{print $2}')
  response=$(curl -s -o /dev/null -w "%{http_code} → %{redirect_url}" "$BASE$old")
  echo "[$old] $response (expected: $BASE$expected)"
done

§ 08 — Deployment & Rollback

Safe Rollout Plan with Rollback

1
Backup Current .htaccess
Before touching anything: cp .htaccess .htaccess.bak.$(date +%Y%m%d). Keep this on the server and locally. If anything breaks, this is your instant rollback.
2
Deploy to Staging First
Upload the new .htaccess and all updated HTML files (with canonical/meta tags) to a staging subdomain (staging.aloftz.com). Run the full curl validation script from §07. Confirm zero 404s and all 301s resolve correctly before touching production.
3
Add Canonical + Meta Tags to All 7 Missing Blog Posts
✓ DONE in v2 ZIP. All 7 blog posts now have correct canonical tags injected. Canonical for blog-paid-ads.html also assigned a unique URL. No manual editing required for this step.
4
Delete Duplicate Files
Remove home.html and blog (1).html from the server. The 301 rules in Block 2 of .htaccess will catch any lingering traffic to these URLs. Confirm they return 301, not 200 or 404.
5
Deploy to Production (Off-Peak Hours)
Deploy between 11 PM–4 AM IST to minimise traffic impact. Upload in this order: (1) updated HTML files, (2) new .htaccess. Do not upload .htaccess until all HTML files are in place — otherwise clean URLs may 404 briefly.
6
Run Validation on Production
Re-run the curl script pointing at production. Open 5 pages in browser and verify source shows correct canonical. Check GSC Coverage → inspect 3 URLs within 24 hours.
7
Resubmit Sitemap to Google Search Console
Update sitemap.xml to use only clean URLs (remove all .html extensions from <loc> entries). Submit in GSC → Sitemaps. Use URL Inspection to request indexing on the 7 previously uncanonicalized blog posts.
8
Rollback Procedure (If Needed)
If any core page breaks: cp .htaccess.bak.YYYYMMDD .htaccess. This instantly restores the previous routing without touching any content files. The HTML files with updated canonical/meta tags are safe to leave in place — they cause no harm even under the old .htaccess.
